The loop

It keeps going between your prompts.

When the lead goes idle, code-kit asks what's next and hands it the step: dispatch the ready stories, review a finished branch, merge the head of the queue. A reviewer agent reads each branch first. Stalled lanes get nudged, then restarted. You choose how hands-off it is, and the band above your prompt always says the goal, what's happening now, what's next, and what's waiting on you.

The rules hold

Advice drifts. Hooks don't.

Rules in a prompt are suggestions an agent forgets three hours in. These are refusals the plugins actually gave while building the book editor, each one saying why and what to do instead.

Lanes

Each lane agent writes only its own paths. The lead writes contracts and specs, and delegates the rest.

⇵

Layers

Each layer imports only what it may, checked before the write, so a layer is never broken on disk.

✓

Proof before done

No agent finishes with failing checks, unowned changes or work nobody committed.

◆

Approvals on the record

Contracts, kit changes and new packages are approved by you or within rules you set, and logged in git.

The why, kept in git

Every file has a card. Every rule has a reason.

Context Graph keeps a small graph beside your code: modules, the rules that apply to them, the decisions made and why, and a card for every file. An agent gets the card and the rules at the moment it's about to edit, and leaves a decision behind when it's done. A background writer cards the existing code; a curator proposes the rules your decisions keep making.

It found the plugins' own bugs, too.

Building something real is the best test. Every one of these was fixed, with a test, before the next release.

  • The first merge was impossible. A new repository had no rules on main to delegate from. Now the first merge is yours, and everything says so.
  • The loop asked twenty times. It now stops after two prompts for one step and asks you instead.
  • Text was mistaken for commands. An echo that mentioned npm install was refused as a new dependency.
  • A helper was blamed for the lead's work. The card writer was flagged for files the lead hadn't committed.
  • The card writer wouldn't take no. Declining one batch brought the next ten. Now no means no, for the session.
