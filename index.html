Two free plugins for Claude Code

Your agents,building like a team that knows why.

Claude Code can split a big job across several AI agents working at once. Left alone, they step on each other: one edits another's files, shortcuts creep into your architecture, and nobody remembers why the code is the way it is. code-kit gives each agent its own part of the codebase and checks its work before it can call it done. Context Graph keeps a short note on why each file exists, and makes an agent read a file before it's allowed to change it.

How it works

One lead, a few specialists, and rules they can't skip.

You describe what you want built. Claude Code becomes the lead and works out a plan with you. Then it hands the work to specialist agents and keeps them in line. Six words cover most of it:

◎

The lead

Your main Claude Code session. It plans the work, hands out tasks, reviews what comes back and merges it. It doesn't build the features itself.

▤

Lanes

Areas of the codebase, each with its own agent: say, the web pages, the database, the AI calls. An agent can only change files in its own lane.

☐

Stories

The plan's tasks, small enough to build and test in one go: "a settings screen where you paste your API key". Each one names the requirements it delivers.

⇵

Layers

The parts of your architecture and which may depend on which. If the business logic must never talk to the database directly, an agent can't make it.

✎

Cards

A few sentences per file, kept in git: what the file is for, what it relies on, and what it must keep true. Agents read it before they edit, and update it after.

◇

Rules and decisions

The conventions your code follows ("money is always stored in cents") and the record of why each change was made, so the next agent doesn't undo it.

While you're away

It keeps working between your messages.

When the lead finishes one thing, code-kit hands it the next: start the tasks that are ready, review finished work, merge what passed. If an agent goes quiet, it's nudged, then restarted. You decide how much it does without asking. A short summary above your prompt always shows the goal, what's happening now, what comes next, and anything waiting on you.

The rules hold

Instructions get forgotten. Checks don't.

Telling an AI agent the rules in a prompt works for a while, then it drifts. These plugins hook into every action an agent takes and stop the ones that break your rules, explaining why and what to do instead. Here are real examples from building one app.

The web pages agent ran its tests, and the test tool quietly rewrote a shared settings file it doesn't own.tsconfig.json
✗ The web-engineer (web lane) may not write tsconfig.json (owned by the lead). code-kit

Why it matters: one agent's side effect would have changed the build for every other agent.
The web pages agent wrote a screen test that reached straight into the server code.src/ui/download.test.ts → @/server/http
✗ Blocked: this edit would break the layer rules: ui may depend on contracts, domain. code-kit

Why it matters: the screens are meant to be independent of the server. The shortcut never reached the disk.
The lead tried to add four libraries to the project.npm install next react react-dom zod
✗ Blocked: a new dependency needs a person's approval, or the lead's, within the rules the project set. code-kit

Why it matters: nothing enters your project without someone deciding it should, and the decision is recorded.
The file import agent started writing code before checking its task against the spec.tests/fixtures/manuscripts/sample.pdf
✗ Run the spec check before writing code on this branch, then continue. code-kit

Why it matters: the agent first lists every requirement it must meet, and any question it has, so it builds the right thing.
The file import agent tried to change a file it had only seen in a search result.src/adapters/parsers/epub.ts
✗ epub.ts has no card yet: read it in full before editing it, and write its card after. Context Graph

Why it matters: changes made from a glance are how code ends up right line by line and wrong for the project.
The lead tried to merge the very first piece of work into the main branch by itself.merge into main
✗ The first merge, which brings the project's rules onto main, is the person's. code-kit

Why it matters: you sign off the rules once. After that, the lead can merge work that passes every check.
Context Graph

Every file explains itself.

An AI agent only knows what it read in this session, and forgets it when the session ends. Context Graph writes the important parts down, next to your code in git: a card for each file, the rules each part of the project follows, and the reasons behind past decisions. When an agent is about to change a file, it gets exactly that file's card, rules and history. When it's done, it leaves a note on what it changed and why.

file src/adapters/parsers/pdf.ts its card Reads a PDF page by page, dropping page numbers and running heads, and keeps the position of each line so a paragraph can point back to where it came from in the original. rules that apply Readers only use the interfaces defined in the core of the app.
Nothing secret is ever committed. decisions on it ingest agent A line that's only a number is a page number and is dropped; Roman numerals are kept, since they can be chapter headings. ingest agent Each line keeps its position, for the panel that shows the original page.

The whole project at a glance.

Context Graph draws the parts of your project as a tree. Each box shows how many rules that part has and how many of its files have a card: “3r 21/21” means three rules, and all 21 files have one. In the desktop app a ring fills as the cards are written. A box pulses blue when an agent records a decision there. If agents keep working around one of its rules, it turns red, and Context Graph suggests rewording the rule for you to accept or reject.

Drawn by Context Graph's own code, from the book editor's real modules. Switch between the desktop app and the terminal to see both.

Both together

See which files each agent is working on.

For any task, code-kit's code map lays out the files it touches, grouped by part of the architecture, with lines showing which file uses which. A file lights up in an agent's colour while that agent reads or changes it, and says whether its why is written, out of date, or missing. Step through the files to read each one's card.

A real build

From a one-paragraph idea to a working app.

We asked for a book editor: upload a manuscript, have AI suggest grammar and flow fixes for each paragraph without changing the writer's voice, see the original and the suggestion side by side, and accept the changes you like. Claude Code worked out the specification with us, split it into tasks, and built it with a team of agents, with both plugins switched on throughout.

Install

Two commands each. Then say what you're building.

You need Claude Code, Node 22 or later, and git. Type these into Claude Code. Neither plugin enforces anything until you've read and approved the rules it suggests for your project, and you can use either one on its own.
